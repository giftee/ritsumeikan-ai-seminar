# Reviewコメント例

## コメント例1: 具体的なRequest changes

好みタグの一致数で並べ、同点時に安いギフトを選ぶ方針は、Issue #1 の目的と合っています。
PR本文にも、外部API連携や自由文生成を今回の範囲外にした理由が書かれていて、差分も小さく追いやすいです。

一方で、「除外カテゴリは好みに合っていても候補にしない」ケースがテスト差分から読み取りづらいです。
次のような制約違反を防ぐテストを追加してからApproveしたいです。

- excludedCategories: `["convenience_store"]`
- 除外カテゴリのギフト: `コンビニスイーツ`
- 代替候補: `カフェチケット`
- expected: `カフェチケット`

判断: Request changes
