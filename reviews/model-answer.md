# 模範回答

## 「決まっていないこと」リストの模範（Part 3 手順2）

画面とコードから分かっていること:

- 避けたいカテゴリ（コンビニ）のギフトが推薦され、`要レビュー` と表示されている
- 現在の実装は在庫と予算しか見ていない（`src/giftRecommendation.js`）
- 既存テストは候補なしの1件のみ

決まっていないこと:

- 条件を満たす候補が複数残ったとき、どの順で選ぶか
- 好みタグに1つも一致しないギフトは候補にするか
- 一致数が同じときの決め方
- 変更してよいファイルの範囲

これらはすべてIssue #1の完了条件で決められています。後半のハンズオンで答え合わせをします。「症状（好みに合わないギフトが選ばれる）だけでは作業範囲が決まらない」ことが、ここでの気づきです。

## AI依頼文の模範（Part 3 手順3）

あなたはペアプロ相手です。
以下の推薦ロジックを直したいです。まず実装せず、次を出してください。

1. 仕様の理解
2. 仕様として決まっていない点（推測で決めず、質問として列挙する）
3. 修正方針の案
4. 追加すべきテストの案

現在の問題: 研究室条件で、避けたいカテゴリ（コンビニ）の `コンビニスイーツ` が推薦されてしまう。

分かっていること: 予算内、在庫あり、避けたいカテゴリ以外で、好みに合うギフトを1つおすすめしたい。対象は `src/giftRecommendation.js` と `test/giftRecommendation.test.js` の2ファイルに限定。候補がなければ `おすすめできるギフトがありません` を返す。

決まっていないこと: 候補が複数残ったときの並び順。好みタグに1つも一致しない場合の扱い。同点のときの決め方。

お願い: 決まっていない点を勝手に決めて実装方針にしないでください。まず質問として出してください。

## Plan Gate判断の模範（Part 3 手順4 サンプル計画）

判断: まだ進めない（Request changes相当）

理由:

- 同点時の決め方を「五十音順」と勝手に決めていて、質問として出していない
- SNSトレンドAPIは、頼んでいない外部API連携の追加（スコープ逸脱）
- 直したい問題そのもの（避けたいカテゴリの除外）と同点時のテストが、追加テスト一覧にない
- 変更範囲を `src/app.js` まで広げている（依頼は2ファイル限定）

ポイント: 修正方針の1〜3と6は妥当です。問題は、計画が間違っていることではなく、決まっていない点を質問せずに埋めていることと、依頼していないことを足していることです。
